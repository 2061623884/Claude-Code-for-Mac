# Claude UI 下一阶段优化方案

状态：四项功能已实现，已安装本地版本 0.3.13。258 项自动化测试、类型检查及 Electron 界面检查通过，等待用户实测。
依据：用户确认动效跟随最新执行位置，并提出会话配置持久化、消息队列、空输入框按 ↑ 召回上一条消息。

## 目标和实施顺序

1. 动效跟随当前执行位置。
2. 按会话持久化模型、思考程度和权限模式。
3. 建立可见、可控制的待发消息队列。
4. 实现输入历史召回。

用户已确认本方案总体方向，并明确要求队列支持编辑、立即插入和删除。立即插入的执行语义如下，实施时须核对 SDK 能力，不能把“已提交”误报成“已执行”。后续真实模型测试使用 Sonnet 5.5，思考程度 Low；不因此修改用户的全局默认配置。

## 一、执行动效跟随当前活动

### 现状

`ChatView.tsx` 在每轮回复正文之前放置 `ThinkingSummary`；`ThinkingSummary.tsx` 将执行动效和思考摘要放在一起。工具和文字不断追加时，动效仍留在开头。现有 `TurnActivity` 有执行阶段和工具 ID，但没有完整的文字块位置。

### 建议行为

- 主会话只显示一处全局执行动效。
- 执行工具时，动效放在当前活动工具行附近。
- 输出文字时，动效位于最新活动文本块末尾下方，随着内容增长向下移动。优先使用块级位置，避免逐字符移动导致排版抖动。
- 暂时没有可展示正文时，在当前执行末尾显示工作状态；开始新的思考阶段时，可在此展示最新摘要，已完成的思考摘要保留为可展开记录。
- 等待用户确认时显示静态等待状态；停止中显示停止状态；完成或失败后结束动画。
- 多个工具同时运行时，各工具保留自己的运行标识，全局动效跟随最近有实际进展的主任务位置，不复制多个全局动效。子 Agent 详情不抢走主会话动效。
- 待发消息不是活动位置。队列新增、编辑或取消不会移动当前任务动效。
- 用户在底部时继续跟随输出；用户向上阅读时不强制滚回底部。动效位置和页面自动滚动分别控制。

### 实施

将实时状态指示器从思考摘要容器中拆出。主进程活动事件携带稳定的消息 ID、内容块索引或工具 ID。前端按活动锚点渲染，不简单把动效放到整个消息列表的最后。锚点尚未到达、指向折叠工具或不可见子记录时，回退到当前主任务末尾。锚点更新与流式正文按同一版本顺序合并，避免迟到事件把动效移回旧位置。

### 验收

工具 → 文字 → 工具 → 文字连续执行时，动效始终跟随实际活动位置。长段流式文字、并行工具、折叠工具、切换会话、排队消息和手动上翻均不造成重复动效或位置倒退。

## 二、会话配置持久化

### 现状

`chatStore.ts` 的 `ChatEntry.options` 位于前端内存。新建缓存条目使用全局默认配置；`ChatSnapshot` 没有返回该会话配置。主进程已有应用存储，但没有完整的按会话配置记录。

### 建议行为

- 会话 A 的模型、思考程度、权限模式，与会话 B 分别保存。
- 切换会话、关闭会话页面、退出并重开 App 后，恢复该会话最后成功保存的配置。
- 新会话才使用全局默认配置。修改全局默认值不改写已有会话。
- 选择“自动/默认”时保留这一选择，不擅自替换为某个具体模型；因此自动解析的实际模型可能随服务端变化。
- 配置恢复不等于任务自动续跑，不能承诺退出 App 后未完成任务仍在运行。
- 模型或模式当前不可用时，显示恢复失败及原因，不静默切到默认值，不扩大权限。
- 旧会话没有本地记录时，优先采用可靠的 SDK 会话信息。无法确认的字段明确标示，不伪称恢复成功。

### 实施

主进程按会话 ID 原子保存配置和版本，并通过打开/重新加载快照返回。配置入口统一，包括选择器、`/model`、`/effort`、计划批准后的模式变化。

活跃会话先取得 SDK 成功确认，再保存已生效字段；部分失败保留已经成功的字段。没有运行进程时保存待恢复配置，下次启动查询前应用，并验证错误。配置写入失败需明确反馈，不能让界面宣称“已保存”。模型、模式、思考程度的变更按会话串行处理，避免快速切换造成覆盖。

从历史编辑分叉出的新会话，初始继承源会话当前配置，之后各自独立。关闭页面不删除配置。

### 验收

两会话使用不同配置，来回切换并重启后仍各自一致。测试模型变更失败、部分字段变更成功、权限受限、旧记录缺字段、分叉及全局默认值变化。

## 三、可见消息队列

### 现状

`PushQueue` 是给 SDK 使用的内存异步输入队列。运行时直接发送会立即交给 SDK，可能被并入当前轮次；它不是用户能管理的待发列表。

### 建议交互

- 空闲时发送立即执行；忙碌时发送默认加入待发队列，输入框上方显示待发数量和内容预览。
- 明确标注“当前任务结束后发送”，不把排队成功显示成已经执行。
- 首版提供编辑、立即插入、删除和清空待发消息。普通待发消息按先入先出顺序发送；拖拽排序可后续另做。
- 编辑：修改尚未提交的队列项，确认后保存，不改变其排队位置。
- 立即插入：选中的队列项绕过等待当前任务完成的规则，立即向当前会话提交，作为对正在执行任务的补充或修正；不默认停止当前任务或强行取消工具。实际消费时机由 SDK 决定，不承诺正在运行的工具立即读到新指令。
- 立即插入采用当前正在执行会话的配置，不在同一任务中途切换模型或权限；操作前在该项显示这一规则。原队列配置快照用于普通排队派发。
- 提交后从可编辑待发列表移出，标记为已提交、等待接收；只有 SDK 确认消费后才标记已接收。提交失败时恢复为可处理项并显示原因；提交结果未知时先核对，不自动重复插入。
- 删除：仅删除未提交项，不影响当前执行任务和其他队列项。
- 自动派发一次只向 SDK 提交一条待发消息。下一条等待当前执行明确完成且会话可继续时再提交，不用气泡位置或动画是否停止作为依据。用户主动立即插入是明确例外，需与自动派发共用提交锁及 UUID 去重，避免同一项被提交两次。
- 建议每条待发消息保存入队时的模型、思考程度、权限模式，并显示配置摘要。修改会话配置不静默改写已排队消息；发送前应用该条配置，失败则暂停队列。
- 当前任务失败、用户停止或需要权限确认时暂停派发，保留待发内容。用户停止只停止当前任务，不隐式删除队列。停止中或连接不可用时禁用立即插入；权限确认期间不允许借立即插入绕过确认。
- 离开会话页面时，App 仍运行则可继续派发。退出 App 后保存队列；重新打开时先暂停，显示待发列表，由用户选择继续。
- 尚未提交的队列项可以修改或删除。已交给 SDK 的消息按执行状态管理，不伪装为仍可撤回的待发消息。

### 实施

在主进程建立按会话持久化的队列，独立于 SDK 输入流。每条记录保存 UUID、原文、附件引用、配置快照和状态。状态至少区分待发、提交中、已确认、失败和提交结果未知。

交付给 SDK 时沿用消息 UUID，结合 SDK 的回声、结果关联字段及队列计数确认消费。崩溃发生在提交与确认之间时，先核对历史；无法确认则展示“提交结果未知”，不自动重发。应用不能仅靠内存队列承诺跨进程严格只执行一次。

附件在入队和派发前检查可用性。历史分叉默认不复制源会话待发队列。确保排队消息不会影响当前活动锚点和已执行轮次分组。

### 验收

连续排入三条，普通派发严格按顺序执行。选中第二条立即插入时，剩余第一、第三条相对顺序不变；双击插入、自动派发与插入同时发生均不得重复提交。覆盖编辑、删除、暂停、确认等待、执行失败、重启、提交确认期间退出、附件丢失和配置应用失败。确认插入不会强制终止当前工具，不会提前把动效移到尚未消费的消息；不得自动重复提交。

## 四、空输入框按 ↑ 召回历史

### 建议行为

- 当前会话输入框为空，按 ↑ 将最近一条真人已发送消息放回输入框，只填入，不自动发送。
- 继续按 ↑ 浏览更早的真人消息，按 ↓ 返回更新消息，越过最新一条回到原空草稿。
- 用户开始修改召回内容后退出历史浏览模式；普通方向键恢复光标移动，不覆盖正在编辑的文字。
- 存在正文、附件或输入法组合输入时，不触发召回。命令补全等弹出列表优先处理方向键。
- 只读取当前会话已确认的真人原文，不读取内部说明、Agent 消息、尚未发送的排队项或来源不明的历史内容。
- 首版召回文字，不自动重新附加历史附件。重复文本保留独立消息顺序。

### 实施与验收

在 Composer 的键盘处理链中加入受限的历史浏览状态，使用消息 UUID 和真人原文，而不是从界面 DOM 提取文字。会话切换时重置浏览索引。

验证空输入召回、上下浏览、编辑后退出、不自动发送、中文输入法、补全列表、附件草稿和跨会话隔离。

## 测试与发布

按四项分别实施和验收，先完成动效，再完成配置持久化，最后接入队列与快捷键。自动化重点验证状态、身份和时序；动效另做实际界面检查。

真实模型验证使用 Sonnet 5.5、Low。如当前账户或 SDK 不提供该模型，先报告，不自行换用其他型号。配置持久化测试可用模拟不同配置覆盖，不必为每个组合消耗模型额度。

完成后再打包安装；当前文档不代表上述功能已经完成。


## 0.3.8 实现记录

- 执行动效从思考摘要中拆出，按实际消息块或工具 ID 定位；实时文字继续写入较早创建的消息时，也跟随其实际更新位置。
- 会话配置与待发队列由主进程按会话 ID 原子保存。旧会话没有保存配置时显示提示，不声称已恢复；新会话及配置变更从此版本起持久化。
- 队列支持编辑、立即插入、删除、清空待发、暂停与继续。立即插入保留原消息 UUID，使用当前执行配置，不调用工具中断。
- 退出恢复时暂停队列。无法确认消费结果的提交保留为未知，不自动重发；用户核对会话后可移除该记录，移除不发送也不取消任务。
- 空输入框 ↑/↓ 浏览当前会话的已确认真人原文，编辑后退出浏览，输入法组合输入不触发。
- 自动化覆盖配置独立恢复、拒绝设置、队列顺序和去重、停止后暂停、附件有效性、活动锚点及键盘浏览。Electron 检查覆盖动效、队列按钮与实际键盘事件。
- 本轮未调用付费模型或执行真实长任务。SDK 插话在真实任务中的消费时机，以及实际账户下的模型恢复，仍需用户实测；如后续调用模型，继续限定 Sonnet 5.5 / Low。


## 0.3.10 队列编辑交互

点击笔图标后，在主输入框编辑。原队列项保留 ID 和顺序，编辑期间锁定，不参与自动派发；不会越过正在编辑的队首项发送后面的消息。保存只更新该队列项，取消保留原文，普通草稿及附件独立保留并恢复。编辑稿在同一次 App 运行期间按会话保存，切换会话后可继续编辑。重启时释放遗留编辑锁并暂停队列，保留原队列内容，不承诺恢复尚未保存的编辑稿。

当前任务在编辑期间结束时，保存或取消后队列保持暂停，需点击继续队列；避免保存操作直接触发任务执行。验证包括后端编辑锁、原位置、原文保留、已有草稿恢复，以及 Electron 实际主输入框编辑/取消/保存/切换会话检查。


## 0.3.12 队列拖拽排序

左侧现有图标前增加六点拖拽手柄。待发消息可拖到另一条待发消息之前或之后，插入位置以高亮线提示；多条消息溢出时靠近列表边缘自动滚动。焦点位于手柄时也可用上下键移动。排序按消息 UUID 提交到主进程并持久化，原文、附件、配置不变。已提交及编辑中的记录保持原槽位；提交状态在拖动期间发生变化时拒绝陈旧排序，不撤回任务或重复发送。


## 0.3.13 队列收尾与正常发送恢复

发送入口只把真正待发/失败/编辑中的条目视为排队任务。会话空闲且没有这些条目时，新手动输入直接发送，并释放旧交付记录遗留的暂停状态；旧提交记录不会重新发送。自动派发不把未知的历史交付记录视为正在执行的输入，暂停的真实待发队列仍需用户继续。

主会话在本轮回复中报告的已消费消息 UUID 会累计到结果事件中，即使最终结果缺少 UUID，也能清理已确认完成的队列项。子 Agent 的关联字段不参与主会话收尾。新增回归覆盖缺少最终关联字段、旧未知记录、新手动输入及后续连续排队，完整测试 258 项通过。
