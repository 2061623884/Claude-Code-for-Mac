# v0.3.40 启动与会话边界审查

## 发现与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 首页先查用户目录，模型选择器再查项目，命令补全挂载时也可对同一项目启动 CLI | 进程竞争，模型和手动 effort 一起等待。每次重启丢失模型能力 | 主进程在打开窗口时预读首个项目。相同配置与目录合并进行中的模型请求。命令按需读取，且可接收初始化结果中的命令；已有会话发布的新命令优先 |
| 模型组件各自等待初始化，只有成功或加载中两种主要表现 | 查询失败时菜单可能长期没有选项。CLI 切换后进程内的旧模型也可能被重用 | 首页、会话、设置和斜杠命令使用同一选择器。区分缓存、校验、失败、空目录。自动 effort 可立即选择，过期响应不能覆盖新项目 |
| 打包版同步运行登录 shell 读取 PATH | 窗口创建受 shell 脚本影响，原有超时是 3 秒 | 异步读取 PATH，准备窗口与环境并行，SDK 查询等待环境准备好再创建子进程 |
| 会话初始化和用户刚提交的设置更新可以交错 | 初始自动档位可能覆盖刚选择的 high | 已启动会话完成初始配置后再处理用户修改。离线设置仍可保存 |
| 带桌面 preload 的主窗口允许网页顶层导航 | 替换桌面文档的页面可能取得桌面桥接 API | 主框架只允许当前入口文档的导航与重定向。网页侧栏有独立 WebContents。隐藏窗口测试覆盖拦截和 iframe 正常加载 |
| 文件恢复按钮直接执行写操作 | 误点可能覆盖工作区已有内容 | 从 SDK 的 dry run 显示影响文件，再明确确认写入。取消不会调用恢复接口 |

Electron 窗口测试还复现了消息队列遮挡活动文案的问题。常规宽度下，队列贴在输入框右上缘，左侧给状态文字留出空间。窄窗口中两者分层显示。测试同时检查可访问状态、动态动作和两者的实际边界。

模型缓存仅保存 CLI 返回的显示名称、模型标识、支持的 effort，以及缓存键和时间。缓存键包括项目目录、应用版本、CLI 路径与文件指纹、Claude 配置目录。文件通过临时文件和重命名更新，权限为 0600。内存结果五分钟有效，磁盘展示结果七天有效。进程重启时始终向本机 CLI 复核。登录身份或项目策略在外部改变时，上一次结果可能短暂过时；界面标明缓存状态。权威查询返回空列表会清除旧结果并允许立即重试。

## 本机测量

使用同一台 Apple Silicon Mac、同一测试项目和内置 CLI。基线为修复前工作区的生产构建。每次启动一个新的 Electron 进程，脚本实际打开菜单、选择模型，随后打开 effort 菜单检查手动档位。下表从首页的模型按钮出现开始计时。每种条件采样三次，单位为毫秒。

| 条件 | 模型可选 | 手动 effort 可选 |
| --- | --- | --- |
| 修复前，无模型缓存 | 3370 / 1052 / 3394 | 3374 / 1058 / 3399 |
| 修复前，复用已有应用数据重启 | 3667 / 3287 / 1095 | 3671 / 3292 / 1098 |
| 修复后，无模型缓存 | 2555 / 3142 / 627 | 2559 / 3146 / 630 |
| 修复后，同一项目有有效缓存 | 3 / 4 / 4 | 8 / 7 / 8 |

这些是单机端到端菜单测量。它们包含界面操作和采样间隔。首次使用仍受本机 CLI 初始化及配置影响，三次采样无法推断其他设备的尾延迟。已有缓存时，手动档位可在实时查询完成前选择。模型输出延迟不在本次基准的测量范围内。

复现时把两个路径指向新建的测试目录。重复使用同一组目录可测试跨进程缓存。脚本只读模型元数据，不提交对话。

```sh
npm run build
CLAUDE_STARTUP_DATA=/tmp/desk-model-data CLAUDE_STARTUP_PROJECT=/tmp/desk-model-project \
  env -u ELECTRON_RUN_AS_NODE node_modules/.bin/electron scripts/smoke-model-startup.cjs
```

## 发布验证

- 从拟发布 Git 树导出干净目录，使用 Node.js 24.15.0 和锁文件执行 `npm ci`。Electron 原生 PTY 模块重建、类型检查、68 个测试文件中的 444 项测试和生产构建全部通过。
- 实际启动打包版两次，分别使用空数据和同一数据目录。两次均通过打包内 CLI 读取 4 个模型，在 UI 中选择模型和手动 effort，并用内嵌 PTY 读到真实 shell 输出，关闭后确认子进程退出。没有发送付费模型请求。
- 挂载 DMG 并解压 ZIP，分别验证应用的完整代码签名、`app.asar` 和内置 CLI。CLI 与锁定依赖的二进制一致，保留 Anthropic 签名。桌面应用采用 ad-hoc 签名，未使用 Apple Developer ID 或公证，本机 Gatekeeper 默认评估结果为 `rejected`。

## 审查边界

本次重点覆盖启动、模型与命令目录、进程生命周期、会话参数、恢复写入和分发产物。会话控制层仍通过通用字符串操作和部分动态类型连接到 SDK。升级 SDK 时应优先核对权限、任务和回退操作的返回格式。大量用户的真实设备分布和不同账号的服务端表现未知。
