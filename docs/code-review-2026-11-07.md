# v0.3.51 会话边界与模块依赖修复

本次修复针对 2026-11-07 架构审查中的五项问题。范围包括工作区已有、尚未发布的后台任务界面和生命周期改动，不包含宣传素材的本地修改。

## 行为与职责边界

| 审查问题 | 修复后的行为 | 责任模块 |
| --- | --- | --- |
| 前台 idle 被误当成整个会话空闲 | 后台任务未结束时拒绝配置重载、文件恢复及对话恢复 | `SessionManager.assertInactive` 统一执行操作前置条件 |
| 旧任务运行的完成事件覆盖新运行，面板与摘要互相矛盾 | 按 `run_id` 过滤旧事件；新运行清除上一轮的计时、输出及用量；同一运行完成后不被迟到进度复活 | `SessionActivity` 持有一个 `TaskTracker`，`LiveSession` 从它读取后台任务及占用事实 |
| 输出读取与权限回复共用修改锁 | 读取持有运行实例占用，不进入修改队列；权限回复和任务停止可继续执行；显式替换实例后拒绝旧读取结果 | `SessionRuntimes` 管理占用，`SessionManager.withRuntime` 校验结果所属实例 |
| 字符串操作和 JSON 载荷绕过类型契约 | 各操作使用明确的 IPC 方法、结构化参数和返回类型；畸形参数在 IPC 入口拒绝 | `shared/sessionControl`、`shared/ipc/contract` 与 `ipc/validators` |
| 界面直接兼容 SDK 响应包装 | 主进程内校验并转换权限规则、任务输出；界面只读取应用定义的数据 | `sessionControlProtocol` |
| 文件链接与附件卡片互相导入 | 两个展示组件共用独立的文件导航行为 | `renderer/openPath` |

Git 差异读取改为文件域接口，不再启动聊天进程。任务输出轮询同一时间只保留一个在途请求；切换会话或任务运行版本后，旧结果不能更新新界面。

## 任务事件语义

`background_tasks_changed` 是当前进程完整的后台成员集合。它与 `task_started`、`task_notification` 等边沿事件的相对顺序没有保证，因此成员集合与完成状态分别保存。忙碌及自动回收以成员集合为准；尚未收到集合的 CLI 使用任务事件作为兼容路径。

集合变化不能将前台任务标记为结束。任务明确转回前台时保留其运行状态。进程关闭清空当前任务列表，但保留用于历史投影的运行版本，避免历史旧事件覆盖新运行。
